# Adaptive Learning Courses

Static publisher for courses generated by the `adaptive-learning` skill.

Each course directory is the authoring contract. Do not reorganize generated
course folders for the website. Run the generator whenever the skill creates or
updates a course.

## Source layout

```text
<topic-slug>/
├── index.md
├── knowledge-base.md
├── progress.md
├── graph.html
└── nodes/
    └── N01-<concept-slug>.md
```

The generator discovers every direct child directory containing `index.md`. It
publishes Markdown pages, Obsidian wikilinks, Mermaid diagrams, course
navigation, and existing graph pages.

## Generate the website

```bash
npm install
npm run generate
```

Generated files are written to `dist/`:

```text
dist/
├── index.html
└── <topic-slug>/
    ├── index.html
    ├── knowledge-base/index.html
    ├── graph.html
    └── nodes/<node-slug>/index.html
```

The generator excludes `.obsidian/` and `progress.md` by default. Progress files
contain personal learning history and should not be published accidentally.

## Cloudflare deployment

Import this GitHub repository as a new Cloudflare Workers & Pages project. The
site is deployed as static Worker assets, so no Worker source entrypoint is
required.

Use these build settings:

- **Project name:** `adaptive-learning-courses`
- **Production branch:** `main`
- **Root directory:** `/`
- **Build command:** `npm run generate`
- **Deploy command:** `npm run deploy`
- **Version command:** `npm run version:upload`

Select **Create new token** in the build configuration and keep that generated
build token assigned to this project. Do not add `CLOUDFLARE_API_TOKEN` as a
build variable.

For a manual deployment from an authenticated terminal:

```bash
npm ci
npm run generate
npm run deploy
```

The included `wrangler.toml` deploys `dist/` as static assets and serves the
generated `404.html` for missing routes.

## Publishing rules

- Keep generated course structure compatible with the adaptive-learning skill.
- Use stable topic slugs and node filenames.
- Keep personal progress out of public builds unless explicitly required.
- Treat unresolved wikilinks as generator warnings and fix them before release.
